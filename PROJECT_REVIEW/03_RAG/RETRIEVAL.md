# ResearchNexusAI — Retrieval Architecture

> **Source Implementation:** ackend/app/services/retrieval.py & ackend/app/services/local_evidence.py  
> **Status:** Authoritative RAG Review Note  

---

## 1. Algorithmic Overview
ResearchNexusAI employs a dual-channel hybrid retrieval architecture designed specifically for scientific literature synthesis:
1. **Lexical Channel (BM25):** Token-based inverted indexing optimized for exact scientific keywords, chemical formulas, model names, and domain terminology.
2. **Dense Semantic Channel (Vector Search):** Neural passage embeddings generated by BAAI/bge-base-en-v1.5 and stored in ChromaDB using cosine distance.

## 2. Ingestion & Preprocessing
- Full-text PDFs from ResearchMind_Dataset (687 papers across Artificial Intelligence, Environmental Science, and Interdisciplinary domains) are extracted into JSON structures.
- Passages are chunked via chunk_corpus.py using sliding token windows with context overlap.
- Inverted indexes and token frequency mappings are pickled into ResearchMind_LocalKB/indexes/bm25_index.pkl.
- Dense vectors are batched and inserted into ChromaDB collections.

## 3. Query Execution
- When a query enters services/retrieval.py:
  - BM25 calculates term match scores across all indexed passages.
  - ChromaDB evaluates dense vector similarity between the query embedding and passage embeddings.
  - Candidates from both channels are merged using Reciprocal Rank Fusion (RRF).
